# 0009. Дедупликация телеметрии при MQTT QoS 1

- Status: accepted
- Date: 2026-09-29
- Deciders: scootly team

## Context

ADR-0002 выбран MQTT с QoS 1 — брокер гарантирует «at least once», значит дубликаты
сообщений неизбежны (redelivery после обрыва). Без дедупа: ложные срабатывания
«заряд <20%», дубли GEOADD и событий в Kafka. Брокер сейчас эмулирован
(MQTT Gateway, тег `Emulated`), для прода нужен кластерный.

## Decision

1. Устройство кладёт **msg_id (UUID)** в каждое сообщение телеметрии/статуса.
2. telemetry-service при приёме: **`SETNX dedup:{msg_id}` в Redis, TTL 5 мин**.
   Ключ уже существовал → дубль, сообщение игнорируется (метрика `mqtt_dedup_dropped_total`).
3. TTL 5 мин покрывает окно redelivery QoS 1; операции — пайплайном с батчем
   GEOADD (см. ADR-0011).
4. **Брокер в проде — кластерный: EMQX или HiveMQ** (финальный выбор — отдельный
   ADR с бенчмарками, продолжение ADR-0002). До прода остаётся эмулятор.

## Consequences

- Плюсы: ровно-once эффект на стороне консюмера без изменений протокола;
  дедуп живёт в Redis, который уже есть.
- Минусы: +1 Redis-операция на сообщение (при 6300 устройствах — приемлемо);
  полный рестарт Redis > 5 мин теоретически может пропустить дубль — не критично
  (дубль телеметрии идемпотентен по сути).
