# 0013. Зависимость от Telegram — accepted risk

- Status: accepted
- Date: 2026-09-29
- Deciders: scootly team

## Context

Весь клиентский контур завязан на Telegram: Mini App как единственный UI
пользователя и Bot API как единственный канал уведомлений (включая алерты
Grafana). Это внешняя платформа без SLA перед нами: лимиты API, риск блокировки,
регуляторные риски.

## Decision

1. Принимаем зависимость как **accepted risk** на этап MVP/пет-проекта —
   отдельный канал не строим.
2. Триггеры пересмотра:
   - **> 30k DAU** (лимиты и стабильность Bot API становятся узким местом);
   - инцидент блокировки/деградации Bot API, повлиявший на пользователей.
3. План Б при триггере: уведомления → **SMS/push** (notification-service уже
   изолирован за Kafka-топиком `notification.send.v1` — меняется только адаптер),
   клиент → native-приложение (React Native база уже есть у оператора).

## Consequences

- Плюсы: нулевая стоимость дистрибуции и авторизации (init-data), быстрый MVP.
- Минусы: единственная точка внешнего отказа контура пользователя; митигируется
  изоляцией notification-service и явными триггерами выхода.
